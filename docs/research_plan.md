# План исследования

План уточнён по комментариям руководителя 2026-09-08.

## Общий протокол

Основная рабочая гипотеза — binary semantic segmentation поражения (`1`) и
фона (`0`). До сравнения архитектур фиксируются PlantSeg v3 split, seed,
preprocessing и правила метрик.

Основные метрики:

- foreground IoU — главная метрика качества поражённой области;
- mean IoU background/foreground — публикуется отдельно и не смешивается с
  foreground IoU;
- Dice, precision, recall;
- pixel average precision — площадь под pixel-level precision-recall curve.

Термин `mAP` без уточнения неоднозначен. COCO mask AP измеряет instance masks и
не эквивалентен pixel AP текущей semantic-задачи. В отчёте нужно явно указать,
какой вариант ожидает руководитель.

## Направление A — точность

Эксперименты выполняются ступенчато, меняя по одному существенному фактору:

1. Frozen ViT-B/16: linear head и простая convolutional head.
2. Размер изображения 384 → 512 → 768 с сохранением aspect ratio и crop.
3. Multi-layer decoder из четырёх промежуточных уровней DINOv3 (DPT/UPerNet).
4. Частичное размораживание последних 2–4 transformer blocks с меньшим LR.
5. ViT-L/16 для лучших конфигураций ViT-B; веса брать через ModelScope.
6. Для финалистов: три seeds, scheduler, class-balanced sampling/loss и TTA.

После каждого запуска сохраняются лучшие, медианные и худшие по foreground IoU
примеры. Карта ошибок использует зелёный для TP, красный для FP и синий для FN.

### SAM

Vanilla SAM нельзя честно сравнивать с fully automatic DINO без prompt
protocol. Нужны как минимум два отдельных режима:

- oracle prompts: точка/box построены из ground-truth, измеряется качество mask
  decoder при хорошем prompt;
- automatic prompts: prompts строятся без test-разметки, измеряется полный
  практический pipeline.

Fine-tuning сравнивается только при одинаковом train split и бюджете разметки.

## Направление B — минимизация данных

Сначала фиксируется полный-data baseline, затем для каждого бюджета проводится
не меньше трёх seeds:

1. random sampling как обязательная нижняя граница;
2. k-means по image/patch embeddings с выбором ближайших к центроидам;
3. k-medoids, где выбранные представители гарантированно являются объектами
   датасета;
4. Farthest Point Sampling для максимального покрытия feature space;
5. при необходимости — комбинация diversity и uncertainty после первого
   обученного probe.

Бюджет следует задавать и общей долей данных, и минимальным числом изображений
на disease class, иначе редкие заболевания могут полностью исчезнуть из train.
Основной итог — кривая качества относительно числа размеченных изображений и
стоимости выбора, а не только одна лучшая точка.

## Ближайшая контрольная точка

До перехода к SAM и data selection необходимо получить:

- результат binary DINOv3 больше одной эпохи;
- согласованные IoU/AP определения;
- таблицу linear против convolutional decoder;
- визуализацию предсказаний и типичных FP/FN;
- короткий анализ, какие болезни и типы сцен дают основные ошибки.
